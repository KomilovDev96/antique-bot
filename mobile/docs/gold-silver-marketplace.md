## ВАЖНОЕ ДОПОЛНЕНИЕ: GOLD & SILVER MARKETPLACE

Marketplace приложения предназначен не только для антиквариата.

Пользователь должен иметь возможность покупать и продавать:

* золото;
* серебро;
* золотые монеты;
* серебряные монеты;
* золотые слитки;
* серебряные слитки;
* инвестиционные монеты;
* ювелирные изделия;
* антикварные монеты;
* коллекционные монеты;
* медали;
* антиквариат;
* другие ценные и коллекционные предметы.

Поэтому Marketplace нельзя архитектурно привязывать только к `Antique`.

---

# КАТЕГОРИИ MARKETPLACE

Создай универсальную систему категорий:

```text
Marketplace

├── Золото
│   ├── Слитки
│   ├── Монеты
│   ├── Украшения
│   └── Другие изделия

├── Серебро

│   ├── Монеты
│   ├── Украшения
│   └── Другие изделия
│
├── Монеты
├── Банкноты
├── Антиквариат
├── Картины
├── Часы
├── Оружие
├── Медали
├── Марки
├── Книги
├── Украшения

```

Категории должны приходить с backend и не должны быть жестко зашиты в мобильное приложение.

ВАЖНО:

# РАСЧЁТ СТОИМОСТИ

Для золотых/серебряных товаров предусмотреть возможность расчёта ориентировочной стоимости:

```text
Вес × Проба × Цена металла
```

Например:

```text
100 г
999.9 Gold

≈ ориентировочная стоимость металла
```

Но обязательно отделяй:

```text
Metal value
```

от:

```text
Market price
```

Потому что коллекционная монета, антикварное изделие или редкий слиток может стоить значительно больше стоимости самого металла.

# AI ДЛЯ ЗОЛОТА И СЕРЕБРА

AI Scanner должен также работать с золотом и серебром.

Пользователь фотографирует:

* золотую монету;
* серебряную монету;
* слиток;
* украшение;
* медаль;
* другое изделие.

AI должен попытаться определить:

```text
Тип
Металл
Предполагаемая проба
Производитель
Год
Страна
Номинал
Вес, если возможно определить
```

Но AI не должен выдавать пробу или подлинность как гарантированный факт только по фотографии.

Использовать формулировки:

```text
Предположительно:
Золото 999.9

Уверенность:
...
```

Если пользователь хочет профессиональную проверку:

```text
Заказать осмотр
```

---

# INSPECTION / ПРОВЕРКА

Для золота и серебра особенно важна функция:

```text
Заказать проверку
```

Пользователь может отправить:

* фотографии;
* видео;
* вес;
* размеры;
* серийный номер;
* документы;
* описание.

Заявка получает статус:

```text
Ожидает
Получена
На проверке
Нужна дополнительная информация
Проверено
Завершено
Отклонено
```

Результат проверки должен быть отдельным объектом и не смешиваться с AI-предположением.

```text

    37 предметов

    182 предмета

    42 предмета
```

```text

```

Если backend предоставляет актуальные цены, можно дополнительно показывать ориентировочную стоимость металл-позиции.

# ГЛАВНОЕ ИЗМЕНЕНИЕ ПО ПРОДУКТУ

Не называй Marketplace:

```text
Antique Marketplace
```

Используй более универсальную концепцию:

```text
Marketplace
```

А приложение должно объединять:

```text
Collection
+
AI Identification
+
AI Assistant
+
Antiques
+
Gold
+
Silver
+
Coins
+
Marketplace
+
Buy
+
Sell
+
Inspection
```

Архитектура должна позволять в будущем добавлять новые категории без изменения фундаментальной архитектуры приложения.

Особенно важно, чтобы:

```text
Gold
Silver
Antiques
Coins
Collectibles
```

были обычными категориями единой системы `Item / Product`, а не отдельными приложениями или отдельными Marketplace-модулями.
